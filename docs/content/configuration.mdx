Everything is in `config.lua`. Edit the file, restart the resource. tSync runs
with zero edits, and your file is never rewritten — a mistyped key is reported at
boot with the key, the file and the fix.

| Key                | Type         | Default  | Bounds        |
| ------------------ | ------------ | -------- | ------------- |
| `intervalMs`       | number       | `5000`   | min `250`     |
| `radius`           | number       | `150.0`  | `1.0`–`500.0` |
| `vehicleClasses`   | table        | `{ 18 }` | classes 0–22  |
| `vehicleBlacklist` | spawn codes  | `{}`     | —             |
| `vehicleWhitelist` | spawn codes  | `{}`     | —             |

## Config.intervalMs

How long two vehicles may drift apart before being pulled back together.

A **ceiling on drift, not a refresh rate.** Nothing is redrawn between passes —
the lights run on GTA's own timer the whole time, and this is only how often
those timers are restarted together.

Lower is tighter and costs more: each pass walks the vehicles within `radius`.
Below about a second the reset itself starts to read as a stutter.

There is no maximum. A very large value is not a mistake — it is "sync rarely",
which is reasonable on a server whose fleet mostly sits parked.

## Config.radius

Metres. Vehicles further out are left alone.

Lower it and cars visibly snap into step as you drive up to them. The `500`
ceiling guards against a typo'd extra zero: past it the vehicles being walked are
not rendered at all.

## Config.vehicleClasses

GTA vehicle class numbers. **18 is Emergency** — every police car, ambulance and
fire truck in the base game, and what almost every emergency vehicle mod sets
itself to.

```lua
Config.vehicleClasses = { 18, 19 }  -- also Military
```

The full list is in the [FiveM native
reference](https://docs.fivem.net/natives/?_0x29439776AAA00A62).

Write it as a plain list. `Config.vehicleClasses = 18` is the mistake that
actually happens, and it is rejected at boot rather than silently matching
nothing. So is a class outside 0–22, and an empty list.

A vehicle still has to have its lights **on** to be touched. tSync never switches
anything on; it only re-times what is already running.

## Config.vehicleBlacklist

Never sync these, whatever their class.

```lua
Config.vehicleBlacklist = { "firetruk", "ambulance" }
```

Spawn codes are the strings you would use with `/car`, and case does not matter —
they are compared as model hashes, and the hash lowercases.

Reach for it when one model's lights look wrong re-timed, or when a vehicle is
driven by a lighting script tSync cannot detect.

## Config.vehicleWhitelist

Sync **only** these.

```lua
Config.vehicleWhitelist = { "police3", "sheriff2" }
```

<Callout type="warning" title="A non-empty whitelist replaces the class check">
  It does not narrow `vehicleClasses` — it stands in for it. It is for a vehicle
  pack that did **not** ship as class 18.
</Callout>

The blacklist still wins. A model in both lists is never synced, and that is
reported at boot rather than quietly resolved.

## Deferring to another lighting script

**Not configurable, deliberately.**

A vehicle driven by a script that renders its own lights — [tLS](https://timmygstudios.com/software/tls)
— is always skipped. The reset cannot help it: rendered LEDs have no engine timer
behind them, and the reset can clip that script's siren, which shares the flag.

Both resource names are probed. tLS was renamed from `tELS` on 2026-10-24, so a
server that has not renamed its folder still gets the deference.

## What is deliberately not configurable

**Whether to sync your own vehicle.** A driver whose own lights are the one set
out of step with everyone else's would reasonably call that the bug.

**A per-player toggle.** tSync has no visible UI and nothing to opt out of. If
you do not want it, stop the resource.

**A speed or parked-only gate.** Lights drift in convoy exactly as they do
parked, and a convoy is where it is most visible.
